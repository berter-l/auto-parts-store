Auto Parts Store

Это тестовый экземпляр интернет-магазина автозапчастей.
Проект представляет собой REST API для управления каталогом товаров,
корзиной покупок, заказами, блогом и системой аутентификации пользователей.

Важно: Данный проект является демонстрационной версией. Платёжная 
система и некоторые другие функции коммерческого характера были 
намеренно исключены из этой версии для упрощения тестирования 
и демонстрации основного функционала. Проект не предназначен 
для использования в production-среде без добавления 
необходимых компонентов безопасности.

# Система поставщиков

Проект реализует двухэтапную систему регистрации поставщиков:

Администратор создает пользователя с группой "Поставщик" через админ-панель Django

Созданный пользователь регистрирует свою фирму, используя данные, выданные администратором

Обычные пользователи не могут самостоятельно зарегистрироваться как поставщики.

# Каталог товаров:

* Просмотр всех товаров с пагинацией
* Просмотр товаров по подкатегориям
* Детальная информация о товаре
* Полнотекстовый поиск по названию, бренду, описанию и характеристикам
* Кэширование запросов для оптимизации производительности

# Корзина:
* Добавление товаров в корзину
* Просмотр содержимого корзины
* Удаление отдельных товаров из корзины
* Полная очистка корзины

# Заказы:
* Оформление заказа на основе товаров в корзине
* Автоматическое очищение корзины после оформления заказа

# Панель поставщика (доступ только для пользователей с группой "Поставщик")

После того как администратор создал пользователя и назначил ему группу "Поставщик", 
этот пользователь получает доступ к следующим функциям:

* Регистрация фирмы поставщика - заполнение информации о компании
* Создание товаров - добавление новых товаров в каталог (поддерживается как одиночное добавление, так и массовое)
* Просмотр всех товаров, добавленных данной фирмой
* Просмотр детальной информации о любом своем товаре
* Обновление товаров - изменение информации о своих товарах
* Удаление своих товаров из каталога

Все действия поставщиков защищены permissions, которые проверяют, 
что пользователь является зарегистрированным поставщиком и владельцем товара.

# Блог:
* Просмотр списка статей с пагинацией
* Поиск статей по заголовку и содержанию


# Процесс регистрации поставщика

Шаг 1: Действия администратора


Создает нового пользователя

У пользователя выбирает группу "Supplier" (Поставщик)

Сообщает пользователю его email и пароль

Шаг 2: Действия поставщика
1. Пользователь авторизуется в системе с полученными учетными данными
2. Отправляет POST запрос на /supplier/suppliers/ с информацией о своей фирме

После успешной регистрации получает доступ ко всем функциям управления товарами

Обычные пользователи (без группы "Supplier") не могут выполнить регистрацию поставщика - 
при попытке отправки запроса они получат ошибку доступа.

## Запуск проекта

Предварительные требования
Установленные Docker и Docker Compose

# Шаги для запуска:

Клонировать репозиторий

Настройка секретного ключа:

В данном проекте отсутствует файл .env. Секретный ключ Django задается непосредственно в настройках проекта.
При необходимости изменить секретный ключ, его можно указать в файле settings.py в переменной SECRET_KEY.

Для генерации нового секретного ключа можно использовать следующий Python код:


* import secrets
* print(secrets.token_urlsafe(50))

Запустить контейнеры:

1. docker-compose build --no-cache
2. docker-compose up -d

После успешного запуска API будет доступно по адресу: http://localhost:8000

Документация API доступна по адресу: http://localhost:8000/api/schema/swagger-ui/

# Создание суперпользователя

При первом запуске автоматически создается суперпользователь с учетными данными:

* Email: admin@gmail.com
* Password: 1234

Суперпользователь имеет полный доступ ко всем функциям системы, включая управление группами пользователей.

# Создание группы "Supplier":

Группа "Supplier" должна быть создана вручную через админ-панель.

# Для создания поставщика необходимо:

1. Войти в админ-панель под суперпользователем
2. Перейти в раздел управления пользователями
3. Создать нового пользователя
4. В разделе "Groups" выбрать группу "Supplier"


# API Эндпоинты:

* # Аутентификация (/authentication/)

* POST /authentication/ - регистрация обычного пользователя

* POST /authentication/login/ - вход в систему

* POST /authentication/update_token/ - обновление JWT токенов

* POST /authentication/logout/ - выход из системы (blacklist токена)

* # Каталог (/parts/)

* GET /parts/ - список всех товаров с пагинацией

* GET /parts/category/ - список всех категорий

* GET /parts/category/<int:pk>/ - список подкатегорий для указанной категории

* GET /parts/parts/subcategory/<int:pk>/ - товары по подкатегории

* GET /parts/parts/search/ - полнотекстовый поиск товаров

* GET /parts/OnePart/<int:pk>/ - детальная информация о товаре


#  Корзина (/cart/)

* POST /cart/add/<int:id>/ - добавить товар в корзину

* GET /cart/ - просмотр содержимого корзины

* DELETE /cart/delete/<int:id>/ - удалить товар из корзины

* DELETE /cart/all/delete/ - полная очистка корзины
* 

# Заказы (/order/)

* POST /order/ - оформление заказа (товары автоматически берутся из корзины)

# Управление для поставщиков (/supplier/) - доступ только для пользователей с группой Supplier

* POST /supplier/suppliers/ - регистрация фирмы поставщика

* POST /supplier/parts/ - создание товаров (один или несколько)

* GET /supplier/parts/all/ - список всех своих товаров с пагинацией

* GET /supplier/parts/<int:pk>/ - детальная информация о своем товаре

* PATCH /supplier/parts/update/<int:pk>/ - обновление своего товара

* DELETE /supplier/parts/delete/<int:pk>/ - удаление своего товара

# Блог (/blog/)
* GET /blog/ - список всех статей с пагинацией

* GET /blog/blog/search/ - поиск статей по заголовку и содержанию

# Особенности реализации

* Кэширование: Redis используется для кэширования часто запрашиваемых данных. Время жизни кэша варьируется 
от 24 до 120 часов в зависимости от типа данных.

* Поиск: Elasticsearch обеспечивает полнотекстовый поиск с нечетким соответствием (fuzziness) по названию, бренду,
описанию и характеристикам.

* Пагинация: Стандартизированная пагинация для всех списков (StandardResultsSetPagination).

* Логирование.

* Транзакции: Критические операции (создание заказа, регистрация) выполняются в атомарных транзакциях.

* Права доступа: Двухуровневая система разрешений с проверкой группы пользователя и владельца объекта.

* Документация: Автоматическая генерация OpenAPI документации с подробными описаниями эндпоинтов.

* Мониторинг: Интеграция с Prometheus для сбора метрик производительности.

* Периодическая задача: Для поддержания чистоты базы данных и безопасности системы, настроена автоматическая очистка просроченных токенов.
